Applying on behalf of more than one person? Each named profile has its own contact info, work history, learned Q&A answers, and uploaded resumes - completely separate from any other profile. The choice below is saved to THIS browser only, so if you have this extension installed in more than one browser (or browser profile), each one stays pinned to whichever person you pick here, independent of the others - even though they all talk to the same companion service.

"Location" above is the combined display string used on your resume (e.g. "Warsaw, Poland (Remote)") - these are separate because some application forms ask for street address, city, postal code, state, and country as distinct fields rather than one combined location. "State" isn't auto-filled from here on purpose - those questions often carry form-specific conditions (e.g. "N/A unless you live in the US"), so it's left to the Q&A tab instead, which captures the correct answer per form.

Generation

Saved

Mode (tailor per job or use an uploaded resume) and both provider choices (resume generation, Auto Fill answers) now live in the side panel, right where you'd actually change them mid-session. This page is just the deeper, rarely-touched config below: model names, connection details, and prompt instructions - plus a way to test each provider without leaving Settings.

Resume generation is the highest-stakes task - a fabricated employer, role, or date is the worst-case failure, which is why Claude is the default there (the only provider that's held up to the truth-grounding requirements in testing). Auto Fill answers are lower-stakes by design (consequential fields and anything needing a discrete pick are never sent to any provider regardless), so a fast local Ollama model is a reasonable default for that narrower job.
